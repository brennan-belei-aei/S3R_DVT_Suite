================================================================================
1. EXECUTIVE SUMMARY
================================================================================

The two scripts form a collection-and-analysis toolchain:

1. CollectionBeta.py controls the DUT and bench instruments, runs one selected
   test from T1 through T9, records local run metadata/results, and saves raw
   oscilloscope waveform CSV files to the oscilloscope's E:/ drive.

2. AnalysisBeta.py is a graphical launcher for offline analysis of T5, T6, T7,
   and T8 waveform files. It does not contain those workflows as readable source
   modules. Instead, it stores four compressed/base85-encoded Python programs,
   decodes the selected program at runtime, rewrites its folder assignments with
   an AST transformer, loads it into an isolated module namespace, and calls its
   main() function.

CollectionBeta.py is the hardware-facing acquisition layer. AnalysisBeta.py is
an offline dispatcher around embedded analysis implementations. Their practical
interface is the naming and content of the waveform CSV files generated by the
scope during T5-T8.

IMPORTANT CURRENT-CONFIGURATION CONFLICTS

- RATED_POWER_W is 3000 W, while the active T6 and T8 power lists are
  [4000, 5000, 6000] W. The validation in prepare_t6_rf_enable() and
  t8_manual_setpoint_voltage() rejects every active T6/T8 point as above rated
  power. As currently configured, T6 and T8 abort before collecting captures.

- WAVEGEN_ADDRESS and BK9141_ADDRESS are both set to 172.24.243.3, including
  identical socket fallbacks. Unless both logical instruments intentionally map
  to the same endpoint, T7 will attempt to open the waveform generator as the BK
  supply. The BK address comment also still says to replace the placeholder IP.

- CollectionBeta.py describes itself as a first hardware-integration version
  that was not hardware-validated by the author. Treat its limits, wiring,
  polarities, trigger levels, and SCPI assumptions as bench-specific settings
  requiring verification before use.

================================================================================
2. COLLECTIONBETA.PY ARCHITECTURE AND STARTUP FLOW
================================================================================

ENTRY POINT

The module ends with:

    if __name__ == "__main__":
        raise SystemExit(main())

main() performs this sequence:

1. Prints the module documentation and the T1-T9 menu.
2. Reads one numeric test selection from standard input.
3. If T5 was selected, asks whether scope vertical scaling should be dynamic per
   transition or fixed for the entire run.
4. Prints the detailed wiring guide for the selected test.
5. Requires the operator to type WIRED before any instrument connection occurs.
6. Creates Instruments(connect_bk9141=True) only for T7; all other tests skip
   the BK supply connection.
7. Connects to the scope, waveform generator, optional BK supply, and DUT.
8. Calls the selected run_tN() function.
9. Converts normal completion, cancellation, Ctrl+C, and exceptions to process
   exit codes.
10. Always calls inst.close() in a finally block.

EXIT CODES

- 0: selected test completed.
- 1: test aborted because of an exception.
- 2: invalid menu/scaling choice or operator cancellation before connection.
- 130: KeyboardInterrupt.

A second operator gate exists inside every run_tN() through
require_operator_acknowledgement(). Therefore a normal run requires both WIRED
and RUN to be typed.

DEPENDENCIES

- Python standard library: csv, math, sys, time, traceback, dataclasses,
  datetime, pathlib, typing.
- Third party: pyvisa and matplotlib.
- Project-specific: AE_Commands_PMNT_HF_1XX.

The script prepends ../AESpecificDependencies relative to the script location
when that directory exists, then imports AE_Commands_PMNT_HF_1XX. Instrument
connectivity also requires a working VISA backend.

================================================================================
3. USER SETTINGS AND CONFIGURATION MODEL
================================================================================

Most behavior is controlled by module-level constants. This makes bench changes
simple, but settings are global and are not captured from a versioned external
configuration file.

MAJOR SETTING GROUPS

- VISA addresses: scope, waveform generator, BK 9141.
- DUT address and operating frequency.
- rated power and active control/regulation mode constants.
- general command, settling, acquisition, and recovery delays.
- User Port voltage levels and channel assignments.
- per-test point lists, repetitions, trigger settings, and scope scales.
- scope save location and local output root.

OUTPUT LOCATIONS

Local run records:

    <script directory>/Results/<test number>_<YYYYMMDD_HHMMSS>/

Possible local files:

- Run_Configuration.csv
- Cycle_Results.csv
- Event_Log.csv
- T4_Summary.csv
- T4_Transfer_Function.png
- T4_Transfer_Function_Error.png

Raw scope waveforms are not copied into the local run folder. They are commanded
to be saved on the oscilloscope under SCOPE_DRIVE, currently E:/. The local
Cycle_Results.csv records the scope-side paths.

RunContext writes a CSV on every row addition, rebuilding the complete file each
time. This provides incremental persistence if a later step fails, at the cost
of repeated file I/O. Column order is first-seen key order across all rows.

================================================================================
4. INSTRUMENT LIFECYCLE
================================================================================

Instruments.connect()

1. Creates pyvisa.ResourceManager and prints backend/resources.
2. Opens the scope at SCOPE_ADDRESS and queries *IDN?.
3. Tries the waveform generator first as VXI-11 INSTR, then as a raw port-5025
   socket. Socket sessions are assigned newline read/write termination.
4. For T7 only, repeats that strategy for the BK 9141, then programs its selected
   channel for 25 V and a 0.5 A limit with output off.
5. Creates the DUT object using AE_Commands_PMNT_HF_1XX.generator(DUT_ADDRESS).

Instruments.safe_state()

Best-effort cleanup does the following:

- Changes both wavegen channels to 0 V DC and turns both outputs off.
- Turns off the BK supply if connected.
- Attempts Host control mode, then DUT RF off.
- Stops scope acquisition.

Instruments.close() calls safe_state(), closes VISA devices, closes the DUT, and
closes the resource manager. Most cleanup exceptions are suppressed after a
warning so that one failed cleanup action does not block the others.

Developer caution: if an exception occurs before an object is assigned, cleanup
is generally safe because every handle starts as None. However, device-side
state should still be independently verified after an aborted run.

================================================================================
5. COMMON COLLECTION HELPERS
================================================================================

DUT CONFIGURATION

set_host_configuration() selects Host mode, forces RF off, sets fixed frequency,
optionally sets regulation mode, disables frequency mode and pulsing, writes the
power setpoint in tenths of watts, and can turn RF on.

enter_user_port() selects control mode 4 and waits COMMAND_SETTLE_S.

Process status helpers decode command-162 responses. Important bits used here:

- d0 bit 6: RF On Requested.
- d0 bit 5: RF Output On.
- d3 bit 7: CEX lock.

T2/T3 read active regulation mode from reportGeneratorSnapshotData() index 10.
The code explicitly avoids that snapshot wrapper in T1 because its dependency
path can call a Host-only API while the DUT is in User Port mode.

SCOPE CONFIGURATION AND CAPTURE

configure_scope() recalls the default setup for every capture, disables unused
channels, applies per-channel coupling/termination/scale/position/offset, sets
horizontal scale and record length, configures an edge trigger, and selects
single-sequence acquisition.

Termination is actively verified. For 50 ohms the code tries both FIFTY and 50
SCPI spellings. Failure to verify termination aborts the capture setup.

timing_capture() is the shared T5-T8 capture engine:

1. Copies the selected TIMING_CONFIG dictionary.
2. Applies optional per-call overrides.
3. Fully reconfigures the scope.
4. Optionally holds the initial state.
5. Arms the scope, with a trigger-state handshake for T5.
6. Executes the supplied stimulus callback.
7. Polls until the scope reports SAVE or STOP, or times out.
8. Saves configured channels if triggered.
9. Records capture status, trigger settings, labels, and scope file paths.

Important behavior: a trigger timeout is recorded as Triggered=False and does
not automatically raise an exception. The parent test usually continues unless
its later state verification fails.

SCOPE FILE SAVING

save_scope_channels() switches the scope to spreadsheet waveform format and
temporarily raises the VISA timeout to 180 seconds per save. Each channel gets a
unique timestamped name. It restores the original timeout in a finally block.
The method assumes the scope can write to E:/ and does not verify the file by
reading it back.

================================================================================
6. TEST-BY-TEST COLLECTION FLOW
================================================================================

T1: RF ENABLE THRESHOLD

Purpose:
Find rising and falling RF Enable thresholds by sweeping 0-5 V in 10 mV steps.

Hardware/control flow:

- Wavegen CH1 supplies a fixed analog power setpoint.
- Wavegen CH2 sweeps RF Enable.
- DUT is configured in Host mode with RF off, then moved to User Port mode.
- The threshold state is RF On Requested, not RF Output On.
- Each cycle validates that the state is inactive at 0 V and active at 5 V.
- Rising and falling crossings are the first sampled voltages at which the
  Boolean state changes. There is no interpolation.
- Results include rising threshold, falling threshold, and hysteresis.

Default workload: 10 cycles, approximately 501 possible voltage values in each
direction per cycle, with 0.1 s settling at each tested value. Runtime can be
substantial.

T2: DC BIAS REGULATION SELECT THRESHOLD

- Wavegen CH1 sweeps the regulation-select input from 0-5 V and back.
- DUT enters User Port once and is expected to default to Forward mode 6.
- State becomes active when repeated snapshots show External/DC Bias mode 8.
- Two consecutive matching reads are required.
- The shared threshold engine records rising/falling thresholds and hysteresis.

T3: LOAD/DELIVERED REGULATION SELECT THRESHOLD

Same threshold framework as T2, but the active state is Delivered/Real mode 7.
The script and test plan call this Load regulation in operator-facing text.

T4: ANALOG SETPOINT TRANSFER FUNCTION

- Wavegen CH1 controls setpoint and CH2 holds RF Enable high.
- DUT Host setup uses rated power, then User Port mode is entered.
- For each T4_VOLTAGES_V point, the script waits 1 s and takes 10 delivered-power
  readings at 0.1 s intervals.
- It stores average, minimum, maximum, ideal power, watt error, and error percent.
- It computes a linear regression, slope/intercept, R-squared, maximum absolute
  error, and maximum linearity error.
- It creates a transfer-function plot and a two-panel error plot.
- RF Enable is lowered in a finally block.

At 0 V, Error_Percent is intentionally None because percent error relative to a
zero expected value is undefined.

T5: ANALOG SETPOINT TIMING

- Wavegen CH1 generates one-cycle, manually triggered square bursts between the
  ordered voltage pairs in T5_STEPS_V.
- Wavegen CH2 holds RF Enable high.
- Each transition is labeled RISE or FALL and captured separately.
- Scope CH1 monitors analog setpoint; CH2 monitors raw RF and is forced to 50
  ohms.
- T5 uses Normal trigger mode and explicitly confirms an armed trigger state.
- The trigger level is the midpoint of the transition.
- Dynamic vertical mode calculates CH1 and CH2 scale per transition. Fixed mode
  uses the configured dictionaries for the entire run.
- There are 6 transitions per cycle and 10 cycles by default, producing up to
  60 captures and 120 waveform CSV files.

The acquisition script saves raw data only. T5 latency/rise/fall extraction is
performed later by AnalysisBeta.py.

T6: RF ENABLE ON/OFF TIMING

- Wavegen CH1 supplies a fixed analog setpoint for each power level.
- Wavegen CH2 toggles RF Enable low/high.
- Every cycle captures RF ON with a rising trigger, waits for stabilization,
  then captures RF OFF with a falling trigger.
- Scope CH1 is RF Enable, CH2 is RF monitor with dynamic 50-ohm scaling, and CH3
  is labeled RF Detector.
- Default workload is 2 captures x 10 cycles x 3 power points = 60 captures,
  each saving three channels if triggered.

Current blocker: active points 4000/5000/6000 W exceed RATED_POWER_W=3000 W, so
prepare_t6_rf_enable() raises ValueError before data collection.

T7: INTERLOCK RESPONSE TIMING

- Requires the BK 9141 connection.
- Wavegen CH1 supplies setpoint; CH2 supplies RF Enable. Both are positively
  verified as High-Z outputs.
- BK output high (25 V) means the interlock stimulus is restored; BK output off
  creates the falling interlock edge.
- Before each capture, RF Enable is lowered, RF-off is confirmed for three
  consecutive reads, a 1 s delay is applied, and the BK output is turned on and
  verified near 25 V.
- RF Enable is then raised and DUT RF-on is confirmed.
- The scope is armed and BK output is switched off as the capture stimulus.
- Scope CH1 captures interlock falling edge at 15 V; CH2 captures RF envelope.
- After capture, software verifies that DUT RF turns off. Failure aborts and
  attempts an explicit DUT rfOFF().
- Default workload is 10 captures at each of 500, 1500, and 3000 W.

The BK readiness polling happens after OUTP ON. The comments correctly note that
this polling does not delay the electrical edge because the scope is already
armed only for the later OUTP OFF stimulus.

T8: CEX LOCK ACQUISITION

- An external DC supply, changed manually by the operator, sets analog power.
- Wavegen CH1 drives RF Enable; CH2 provides a 13.56 MHz CEX reference.
- For each power point the code disables RF and CEX, prompts the operator to set
  the calculated external voltage, then requires an exact text response such as
  500W.
- Each acquisition verifies the DUT is unlocked, raises RF Enable, arms the
  scope, enables CEX reference as the stimulus, then verifies CEX lock.
- Scope CH1 is CEX reference, CH2 RF waveform, CH3 active-low lock pull-up.
- Cleanup lowers RF Enable and disables CEX, but external supply return to 0 V is
  only printed as a manual instruction.

Current blocker: active points 4000/5000/6000 W exceed RATED_POWER_W=3000 W, so
t8_manual_setpoint_voltage() raises ValueError before operator prompting.

T9: CEX LOCK LOSS

- Configures a sine reference, turns it on, waits for lock, and captures its
  removal.
- Records whether lock existed before removal and whether unlock occurred after.
- It does not perform the same explicit Host/User Port preparation used by T8.
- The connection guide notes T9 is marked "ignore for now" in the supplied plan.

================================================================================
7. ANALYSISBETA.PY ARCHITECTURE AND FLOW
================================================================================

AnalysisBeta.py supports T5-T8 only. It uses tkinter dialogs rather than console
input.

ENTRY FLOW

1. Creates and hides a Tk root window.
2. Prompts for T5, T6, T7, T8, or numeric 1-4.
3. For T5 only, asks whether to apply waveform smoothing.
4. Prompts for the folder containing waveform CSV files.
5. Prompts for an output parent folder.
6. Decodes, rewrites, compiles, and executes the selected embedded analysis.
7. Calls the embedded module's main().
8. Treats None or 0 as success; any other return value is an error.
9. Shows a success or error message box and returns process status 0 or 1.

EMBEDDED SOURCE STORAGE

ANALYSIS_SOURCES maps T5-T8 to large ASCII strings. decode_source() performs:

    base64.b85decode(...)
    zlib.decompress(...)
    UTF-8-SIG decode

This design creates a single-file launcher, but it makes code review, version
diffs, debugging, security review, and maintenance significantly harder. The
embedded source is executable code and should be managed with the same controls
as normal .py files.

AST REWRITING

FolderOverrideTransformer removes every top-level or nested if statement whose
left comparison operand is the name __name__. Its intent is to remove each
embedded script's if __name__ == "__main__" runner.

Inside any function literally named main, it rewrites simple assignments:

- folder = <anything> becomes folder = _selected_input_folder
- output = <BinOp> has only its left operand changed to
  _selected_output_folder

Consequences and limitations:

- Rewriting depends on exact variable names and assignment shapes.
- output must be a single-target assignment whose value is an ast.BinOp.
- If embedded scripts rename folder/output, use annotated assignments, use
  helper functions, or change output expression structure, redirection can fail.
- The __name__ removal logic is broader than an exact main-guard check. Any
  comparison with __name__ on the left is removed, regardless of comparator or
  surrounding intent.

RUNTIME MODULE LOADING

load_analysis_module() creates a new types.ModuleType, injects selected folder
paths, compiles the transformed AST, and exec()utes it. It then requires a
callable main(). Embedded imports and top-level statements execute during exec.

For T5, ENVELOPE_SMOOTHING_S is overridden after module execution:

- enabled: 2.0 microseconds
- disabled: 0.0 seconds

T6-T8 receive no runtime algorithm changes from the launcher.

WHAT CAN AND CANNOT BE CONFIRMED FROM THE READABLE WRAPPER

The wrapper's documentation states that the embedded workflows preserve the
validated standalone numerical algorithms, waveform pairing, thresholds, plots,
CSV columns, and failure handling. However, these details are not visible in the
normal readable body of AnalysisBeta.py. A developer who needs to maintain or
audit those algorithms should decode the embedded programs into separate source
files and review them directly.

================================================================================
8. HOW THE TWO SCRIPTS WORK TOGETHER
================================================================================

- CollectionBeta.py creates unique descriptive scope filenames containing test,
  power/transition, cycle/acquisition, channel, and timestamp.
- T5-T8 analysis expects folders of those waveform CSV files and appears to rely
  on the established standalone workflows' pairing and filename parsing rules.
- AnalysisBeta.py lets the operator select any input folder and a separate
  results parent. The embedded workflow still creates its normal timestamped
  result directory, but under the chosen parent.
- There is no programmatic manifest transfer from CollectionBeta.py to
  AnalysisBeta.py. Correct selection of the intended waveform folder and stable
  naming conventions are therefore important.
- CollectionBeta.py stores raw waveforms on the scope, while its run metadata is
  stored on the controlling PC. A complete archival run requires both locations.

================================================================================
9. ERROR HANDLING AND SAFETY BEHAVIOR
================================================================================

Strengths

- Two explicit operator gates before execution.
- Scope termination is verified instead of assumed.
- T1-T3 validate both sweep endpoints to prevent false thresholds.
- T5 confirms RF-off before setup and confirms scope arming.
- T7 verifies High-Z wavegen load, BK state/voltage, RF-on before stimulus, and
  RF-off after stimulus.
- CSVs are rewritten incrementally after every new record.
- Top-level finally blocks attempt to disable stimuli and place equipment safe.
- Waveform saves use a dedicated long timeout with restoration afterward.

Limitations

- Safe state is best effort and suppresses several exceptions.
- Trigger timeout is usually nonfatal, so a run may finish with missing captures.
- No waveform file integrity or existence verification is performed after scope
  save.
- Some safety-critical settings are comments/constants rather than device-read
  verification, including much of the wiring and probe behavior.
- T8 cannot automatically zero its external setpoint supply.
- T9 has less explicit DUT-state preparation than T5-T8.
- Collection and analysis have no shared machine-readable run manifest.

10. MAINTENANCE RISKS AND RECOMMENDATIONS
================================================================================

PRIORITY 1: FIX ACTIVE CONFIGURATION CONFLICTS

1. Align RATED_POWER_W with the actual DUT or restore T6/T8 power lists that do
   not exceed the rating. Add an early startup validation that checks every
   configured test point before instruments are connected.
2. Set BK9141_ADDRESS and its socket fallback to the BK supply's actual IP.
   Add a check that the wavegen and BK addresses are not identical unless an
   explicit override is enabled.
3. Confirm DUT_ADDRESS. It is currently RFGN075EAA, while other project context
   may use a DUT IP/hostname. Keep one authoritative setting.

PRIORITY 2: MAKE ANALYSIS CODE REVIEWABLE

Decode T5-T8 into normal version-controlled modules and import them. Keep the
single-file packaging step as a build artifact if required, not as the primary
source. Add hashes/version identifiers for each embedded workflow and print them
at runtime.

PRIORITY 3: ADD CONFIGURATION VALIDATION

Before connecting hardware, validate:

- rated power is positive;
- all power lists are nonempty and within rating;
- channel numbers and scope channels are legal;
- setpoint scaling produces permitted voltages;
- cycle/sample counts are positive;
- threshold bounds and step are valid;
- addresses do not conflict;
- output directories and scope drive settings are plausible.

PRIORITY 4: ADD A RUN MANIFEST

Write one JSON or CSV manifest containing script version/hash, all user settings,
selected test, instrument identities, local output paths, scope waveform paths,
start/end time, and completion status. Analysis should consume this manifest or
at minimum copy it into its result directory.

PRIORITY 5: IMPROVE TESTABILITY

Separate pure calculations from hardware I/O and introduce instrument protocol
interfaces or mocks. Unit-test:

- threshold crossing and hysteresis logic;
- voltage/power conversions;
- scope scaling selection;
- process-status bit decoding;
- T4 regression/error calculations;
- filename generation;
- state timeout behavior;
- AST transform behavior against representative embedded source changes.

PRIORITY 6: HANDLE CAPTURE FAILURES EXPLICITLY

Add a configurable policy such as abort, retry N times, or continue. Record retry
count and final reason. For engineering qualification, silently continuing after
missing waveforms can create incomplete datasets that look like completed runs.

PRIORITY 7: REDUCE DUPLICATED/FRAGILE STATE

Consider dataclasses for per-test settings and a common state-machine structure.
The current global-constant design is understandable but permits contradictory
settings and makes automated validation harder.

================================================================================
12. FINAL ASSESSMENT
================================================================================

The collection script has a generally deliberate hardware-control structure,
with useful operator gates, incremental logging, state checks, verified scope
termination, and best-effort cleanup. Its largest immediate issue is not the
control flow but contradictory active settings that make T6 and T8 unrunnable
and may misroute the T7 BK connection.

The analysis launcher is operationally convenient, but embedding opaque
compressed programs is the principal maintainability concern. The wrapper can be
understood and reviewed, but long-term ownership requires the actual T5-T8
analysis sources to exist as readable, testable modules. The recommended next
step is to correct the address/power configuration, then extract and version the
embedded analysis workflows before further algorithm changes.
